# 필요한 외부 스킬과 도구

## 작업에 필요한 것만 확인

현재 요청에 필요한 기능을 먼저 정한다. 사용 가능한 스킬·연결 도구·실행 파일을 확인한다. 단순 답변을 위해 설치하거나 모든 스킬을 일괄 설치하지 않는다. 기존 문서·표·영상·기획 등 전문 스킬을 활용하고 본 스킬이 제작 절차를 대체하지 않는다.

## Aside 웹 검색과 탐색

웹 검색·웹페이지 탐색에는 Aside 스킬과 지정 도구를 사용한다. 사용 전 설치된 Aside 스킬의 현재 지침을 읽는다. 명령어·프로필 선택·연결 방식은 해당 지침에서 확인하며 기억으로 추측하지 않는다. 내장 브라우저나 다른 브라우저 자동화로 임의 대체하지 않는다.

Aside 스킬과 실제 실행 도구/연결 상태를 각각 확인한다. 필요한 구성요소가 없으면 출처와 범위를 설명하고 설치 여부를 묻는다. 설치 전에 공식 출처를 확인할 수 없으면 미확인 웹사이트를 우회 탐색하거나 명령을 실행하지 말고, 제공된 신뢰 가능한 카탈로그·설치 도구를 확인하거나 필요한 안내를 요청한다. 설치나 인증이 막히면 실제 제약과 다음 조치를 알린다. 직원의 계정·프로필은 현재 환경에서 확인하고 타인의 계정으로 임의 전환하지 않는다.

브라우저 작업도 사용자의 실제 마우스·키보드·창 포커스를 방해하지 않는 비전면 방식으로 수행한다. 그 방식으로 불가능하면 실제 입력이나 포커스 전환 전에 제한을 알리고 명시적 허락을 기다린다. 개인 Telegram 발신·수신 계정이나 전달 라우팅은 이 공용 스킬에 정의하지 않는다.

## agent-desktop 데스크톱 직접 조작

사용 전 해당 플랫폼의 agent-desktop 스킬과 CLI 기능을 확인한다. 먼저 대상 앱과 필요한 작업을 식별하고, 사용자 전경 창을 바꾸지 않는 것으로 확인된 전용 API·파일 조작이나 비활성 조회를 사용한다. UI 직접 조작에는 agent-desktop 헤드리스 세션을 시작한다. 스냅샷 전에 같은 세션에서 별도 커서 오버레이를 활성화하고 렌더러 응답을 확인한다. 같은 세션으로 조회와 허용된 조작을 수행하고 오류 시에도 종료한다. 표시 여부를 확인할 수 없으면 제한을 알린다.

UI 변경 **직전마다** 현재 전경 창과 대상 창의 식별자를 확인한다. 사용자 작업 창에 대한 입력 간섭 가능성, 대상 앱 동작과 대화상자 생성 가능성까지 판단한다. 같은 Windows 데스크톱에서 헤드리스 UI Automation의 Invoke로 백그라운드 앱이 활성화된 사례가 있다. 헤드리스 플래그나 전경 창 확인만으로 다음 동작의 안전을 추정하지 않는다.

백그라운드 버튼 실행·메뉴 열기·창 실행 또는 복원·대화상자 호출 등 포커스를 보장할 수 없는 동작은 보내기 전에 건너뛴다. 확인된 비활성 API·파일 경로나 이미 허용된 격리 환경에서 처리한다. 그런 경로가 없으면 해당 동작을 멈추고 이유를 알린다. 실제 마우스·키보드·포커스 전환은 해당 범위의 명시적 허락이 있어야 한다. agent-desktop 지정·설치, 이전 명령 실패나 재시도 가능 응답을 허락으로 확대하지 않는다. 자동 headed/다른 입력 도구 전환, 포커스 탈취 후 원래 창 강제 활성화는 금지한다.

검증 보고에서 ① rendered 응답(렌더러 승인), ② 별도 커서가 실제 대상 위치로 이동한 관찰, ③ 사용자 마우스 좌표 변화, ④ 전경 창 변화는 각각 기록한다. 사용자가 움직이는 마우스의 좌표 변화 원인을 단정하지 않는다. 포커스 보호 대조 시험은 활성화 없이 표시하는 전용 테스트 창에서 조회만 하고 위험한 실행을 사전 생략하여 세션 종료까지 전경 창을 관찰한다. 이미 확인된 탈취 동작을 실사용 창에서 반복하지 않는다.

Windows 문제 해결 사례: npm 1.0.2의 x64 설치에서 세션은 시작됐지만 배포 파일명으로 실행한 오버레이 응답이 false였고, 같은 해시의 사본을 agent-desktop.exe로 실행했을 때 true였다는 관찰이 있다. 해당 버전·증상이 일치할 때만 참고한다. 실행 경로·상태 폴더는 각 PC의 비공개 설정에서 관리한다.

## 설치 승인과 검증

설치가 필요하면 구성요소, 검증된 배포 출처, 설치 위치/범위, 필요한 권한·로그인·비용을 설명하고 명시적 승인을 기다린다. 같은 설치를 이미 승인받았으면 재질문하지 않는다. 답변 없음은 승인이 아니다. 공식 출처를 확인할 수 없으면 미확인 명령으로 설치하지 않는다. 사용 가능한 설치 전용 스킬과 플랫폼 지침을 따른다. 특정 직원 경로나 변경될 수 있는 설치 URL을 공용 기본값으로 하드코딩하지 않는다.

설치 후 버전·인식 여부·해당 작업에 필요한 기능을 검증하고 원래 작업을 재개한다. 로드되지 않으면 새 세션/재시작 필요 여부를 확인한다. 설치·업데이트 실패와 인증·환경 제약을 구분해 알린다. 스킬 설치를 계정 변경·결제·보안 해제·불필요한 권한 확대의 승인으로 해석하지 않는다. 직원별 인증정보를 공용 패키지에 포함하지 않는다.
