# 공유 프로젝트와 중복 폴더 방지

## 동일 프로젝트 식별

사용자가 선택한 루트와 기존 프로젝트 안내를 기준으로 한다. 루트의 표시 이름과 대화 제목을 분리한다. 대화 이름 변경, PC 변경, 보관 하드 이동으로 새 프로젝트 루트를 자동 생성하지 않는다. 새 PC에서는 사용자가 지정한 경로와 안내/자산으로 동일 프로젝트인지 확인한다. 프로젝트 ID를 기록한다면 기존 ID를 재사용하고 로컬 절대경로는 공유 식별자로 쓰지 않는다.

쓰기 전 실제 부모 폴더 목록과 대상 경로를 확인한다. 유사 이름이나 동기화 충돌 사본이 보이면 읽기 전용으로 차이를 확인하여 제안하고, 승인 없이 합치거나 삭제하지 않는다. 잘못된 경로에 빈 파일을 쓰는 것도 변경이다. 경로가 없어졌거나 잠겨 있으면 임의로 다른 루트·옛 이름·번호 붙인 사본을 만들지 않는다.

## Dropbox 공동 작업

- 온라인 전용 파일·미동기화·접근 불가를 파일 부재로 단정하지 않는다. 사용 가능한 상태 확인 수단으로 점검하고 확인할 수 없는 상태는 알린다.
- 여러 직원이 같은 제작 파일을 동시에 편집하지 않도록 담당자와 반영 범위를 확인한다. 순차 편집·인계가 정해져 있으면 그 규칙을 따른다. 담당자가 불명확하고 덮어쓰기 위험이 있으면 질문한다.
- 작업 시작 시 대상의 해시/크기/수정 상태를 기록하고 반영 직전 비교한다. 달라졌으면 반영을 중단하고 변경 내용을 확인한다. 이 비교는 확인과 쓰기 사이의 경쟁까지 막지 않으므로 동시 쓰기 금지 절차를 대체하지 않는다.
- 공유 폴더의 잠금 파일이나 로컬 mkdir 성공만으로 여러 PC의 배타 잠금이 확보됐다고 주장하지 않는다. 확실한 자동 조정이 필요하면 별도 중앙 조정 방식 설계와 승인이 필요하다.
- 임시 렌더·캐시·의존성 등 빈번하게 바뀌는 파일은 승인된 로컬 작업 공간에서 관리하고 공유할 제작 파일·연결 자산·결과물을 구분한다. 임의의 외부 위치는 만들지 않는다. 프로젝트 지침이 내부 작업을 요구하면 우선 따르고 충돌하면 대안을 확인한다.
- 제작 파일을 로컬에서 작업했다면 반영 대상·범위를 기록하고, 검증한 파일만 승인된 공유 위치에 반영한다. 필요한 연결 자산을 누락하지 않는다. 공유 전체 폴더를 미러링하거나 로컬 삭제를 전파하지 않는다.
- 같은 공유 안내 문서를 여러 직원이 갱신할 경우 기존 내용이 변경됐는지 확인하고 순차 반영한다. 충돌 시 대화별 별도 기록을 보존하고 인덱스 통합을 조정한다.
- 저장 성공, 로컬 검증, Dropbox 업로드 상태, 다른 PC 수신 확인을 구분한다. 확인하지 않은 동기화를 완료로 보고하지 않는다.

결과물의 통상적인 `이전안` 보관은 [파일 관리](files.md#결과물-버전-보관)의 상시 승인 범위를 따른다. 이는 공유 파일의 동시 변경 확인을 생략하는 예외가 아니다. 이동 직전 다른 직원의 변경·불확실한 접근 상태가 발견되면 덮어쓰거나 강제 이동하지 않고 보류한다. 원격 동기화 완료는 별도로 확인한다.

## 다른 OS로 인계

Windows·macOS 사이에서도 현재 사용자가 지정한 실제 동기화 루트를 확인한다. 이전 PC의 절대경로를 복사하거나 동기화 위치를 고정 추정하지 않는다. 온라인 전용·미동기화 자료는 먼저 실제 읽기 가능 여부를 확인하고, 다운로드 성공과 다른 PC 수신 성공을 구분한다.

인계받은 환경에서 필요한 제작 파일과 연결 자산을 실제로 열어 확인한다. 앱·폰트·플러그인·코덱의 가용성, 경로 재연결과 결과물 표시 차이를 확인하고 변경이 필요한 항목은 승인 범위에서 처리한다. 복사한 파일의 해시 일치는 바이트 보존의 증거이며 제작 앱의 호환성 증거는 아니다. 운영체제가 생성한 보조 파일을 발견해도 일괄 삭제하지 않는다.

시험은 승인된 위치와 최소 자료로 수행하고 각 PC의 저장·동기화·수신·열기 결과를 따로 기록한다. 한쪽 PC만 관찰했다면 양쪽 검증 완료로 보고하지 않는다.

## 원인 조사와 정리

오타·수동 이름 변경·다른 도구 생성·동기화 충돌을 구분한다. 폴더명과 로컬 생성 시각만으로 원인을 확정하지 않는다. 로그나 활동 이력도 해당 사실만 뒷받침한다. 정리 전 양쪽 자료와 참조 관계를 확인한다. 자동 승인 거절이 발생하면 우회하지 말고 동작과 제공된 사유를 보고한다. 사용자 승인 없는 삭제·병합은 하지 않는다.
