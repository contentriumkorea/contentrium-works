# 파일 관리

## 경로와 분류

사용자가 선택한 실제 프로젝트 루트를 조회해 확인한다. 현재 작업 디렉터리·출력 경로·프로젝트 지침을 대조하고 실행 동안 같은 기준 경로를 사용한다. 대화 제목이나 기억한 폴더명을 타이핑해 루트를 재구성하지 않는다. 루트가 없으면 재생성하지 말고 경로·동기화·접근 상태를 확인한다.

기존 폴더를 먼저 조회한다. 표기·대소문자·공백·유니코드 차이가 있는 유사 폴더도 후보로 확인하되 자동 통합하지 않는다. 프로젝트 타입과 기존 관행에 맞는 최소 분류만 제안한다. 새 폴더의 대상·위치를 승인받은 뒤 만들고 생성 결과를 재조회한다. 사용자 지정 경로와 기존 승인된 분류는 재승인하지 않는다. 아래 결과물 버전 보관에 필요한 `이전안` 및 충돌 격리 하위 폴더는 통상 보관 범위로 추가 승인 없이 생성한다. 이는 프로젝트 루트 재생성이나 무관한 폴더 재분류의 허가가 아니다.

| 작업 | 기존 구조가 없을 때 제안할 예시 |
| --- | --- |
| 영상 | 문서용 상위 분류(예: 서류)와 제작용 분류를 함께 고려. 실제 자료에 따라 Footage: 소스, Sequence: 제작 파일, Export: 렌더링 결과 |
| HyperFrames | Sequence/hyperframes/작업명: 제작·재현 자료, Export: 영상 |
| 기획·견적·계산서·스토리보드 | 기존 서류·문서·etc 등 문서 관리 위치 아래 필요한 업무 분류. 영상 프로젝트의 문서는 아래 기준 참고 |
| 지원사업 | 사업명 아래 공고·신청·증빙·제출 등 현재 필요한 분류 |
| 보고서 | 참고자료·작성 파일·제출본 등 필요한 분류 |
| 소프트웨어·스킬 | 기존 저장소의 src·docs·tests·dist 등 프로젝트 고유 구조 |

위 표는 강제 트리가 아니다. 기존 export/푸티지 등의 이름을 영문 예시로 바꾸지 않는다. 문서 한 개 때문에 대규모 폴더를 만들지 않는다. 실제 생성 이미지·음원은 사용 용도의 자산 폴더, 프롬프트·결정은 작업 기록, 재현에 필요한 도구 프로젝트는 제작 폴더에 둔다.

쓰기 직전에 목적지의 정규화된 실제 경로와 부모가 확인한 루트 안에 있는지 확인한다. 정션·심볼릭 링크로 외부에 쓰는 경우도 외부 저장으로 취급한다. 승인되지 않은 경로를 mkdir -p/New-Item -Force/placeholder 생성으로 만들어 우회하지 않는다. 경로가 없다는 오류는 새 폴더 생성 승인이 아니다.

## 영상 프로젝트의 문서와 제작 자료 분류

영상 프로젝트의 구조를 설계하거나 정리할 때는 계약·기획·촬영 운영·행사 자료뿐 아니라 실제 촬영 소스·편집 프로젝트·렌더링 결과도 함께 들어올 수 있음을 고려한다. 최상위는 자료의 큰 성격으로 나누고, 문서의 업무별 분류는 문서용 상위 폴더 안에 묶는 안을 우선 검토한다. 업무명마다 최상위 폴더를 늘리는 것을 기본값으로 삼지 않는다. 다만 사용자 지시와 기존에 운영 중인 구조가 우선이며, 폴더 수를 줄이기 위해 기존 자료를 자동 재편하지 않는다.

예를 들어 문서가 여러 종류라면 `서류/계약 및 기획/과업이행요청서`, `서류/계약 및 기획/산출내역서`, `서류/계약 및 기획/영상 제작 기획서`, `서류/계약 및 기획/기존 참고 자료`, `서류/촬영 운영/촬영 일정 및 운영계획서`, `서류/촬영 운영/시청 피드백`, `서류/행사 참고자료`처럼 제안할 수 있다. 실제 제작 자료는 필요에 따라 `Footage`, `Sequence`, `Export`, AI 기록은 승인된 `codex`에서 관리한다. 이 경로들은 역할을 설명하는 예시이지 필수 이름·깊이·완성 트리가 아니다. 파일이 적으면 `서류` 또는 업무 폴더에 바로 저장해도 된다.

- 먼저 기존 문서 위치, 제작 파일 위치, 사용자 분류와 실제 자료를 확인한다. 이미 `문서`, `Documents`, `etc` 등이 같은 역할을 하면 재사용한다. 예시와 이름을 맞추려고 `서류`를 추가하거나 기존 폴더를 개명하지 않는다.
- 앞으로 제작 자료가 들어올 가능성은 분류 설계에 반영하되, 아직 없는 자료를 위해 `Footage/Sequence/Export/etc/codex`나 모든 문서 하위 폴더를 미리 만들지 않는다. 지금 저장할 자료에 필요한 경로만 승인 범위에서 생성한다. 비영상 프로젝트에는 영상 폴더 구조를 적용하지 않는다.
- `서류`는 업무 문서를 묶는 역할, `etc`는 기존 프로젝트에서 정의한 기타 자료 역할로 구분할 수 있다. 이미 `etc`가 문서 관리 위치라면 그대로 활용한다. 두 폴더를 동시에 만들거나 같은 문서를 중복 복사하는 것을 기본으로 하지 않는다. 분류가 애매하면 기타 폴더에 무조건 넣지 말고 역할을 제안한다.
- 확장자나 '촬영/행사/참고'라는 이름만으로 위치를 결정하지 않는다. 촬영 일정표·행사 개요는 문서, 편집에 사용하는 행사 영상·이미지·음원은 제작 자산, 편집 프로젝트는 제작 파일이다. 혼합 폴더는 실제 용도와 연결 관계를 확인한다. 동일 자산을 양쪽에서 참고할 때는 기준 위치를 정하고 기록으로 연결하며 자동 중복 복사하지 않는다.
- 이미 최상위에 계약·촬영·행사 폴더가 있다면 그대로 작업할지 문서 상위 폴더로 묶을지 비교해 제안한다. 재분류안에는 기존 경로→제안 경로, 각 범위, 제외할 원본·연결 자산, 의존성·링크 영향과 보존 확인 방법을 명시하고 승인 후 처리한다. 명시적인 정리 위임이 있으면 그 범위에서 진행하되 삭제·덮어쓰기·연결 변경 권한으로 확대하지 않는다.
- 외부 자료는 아래 외부 자료 반입 절차를 따른다. 기존 원본은 보존하고 파일명을 임의로 바꾸지 않는다. 연결된 미디어·제작 파일은 참조와 재연결 가능성을 확인하며 안전성을 확인할 수 없으면 현재 위치를 유지하고 확인을 요청한다. 승인된 이동도 공유 작업의 동시 변경 확인과 이동 전후 보존 검증을 생략하지 않는다.
- 기존안의 `이전안` 보관은 결과물 버전 관리이고, 최상위 구조를 바꾸는 재분류는 별도 작업이다. 통상 버전 보관의 상시 승인을 폴더 재편 승인으로 사용하지 않는다. 분류 변경만으로 파일을 구버전으로 판단하지 않으며 같은 결과물 여부·최신안 묶음·검증 조건을 그대로 적용한다.
- 승인한 역할과 경로를 프로젝트 안내에 남긴다. 실제 이동 후 인계 문서·현재 파일 링크를 갱신하고 이동 전후 위치·보존 검증·유지한 외부 의존성을 기록한다. 과거 이력은 지우지 않는다. 다음 작업은 이 승인된 구조를 재사용한다.

## 외부 자료

외부 자료를 읽어 위치·내용을 파악할 수 있지만, 제작에 가져오기 전 원본·복사 대상·프로젝트 내 목적지를 제안하고 복사 여부를 묻는다. 이미 특정 복사를 지시받았다면 다시 묻지 않는다. 자료 묶음 단위로 승인받고 원본은 보존한다.

승인 후 동명 대상 존재 여부를 확인하고 복사한다. 동일 내용이면 재사용할 수 있는지 확인하며, 다른 내용이면 덮어쓰지 말고 해결안을 제안한다. 파일 수·크기와 필요 시 해시로 복사를 검증한다. 편집 프로젝트의 연결 자산도 확인한다. 실제 가져오기·참조·편집·실행·렌더링을 복사본 경로로 전환하고 앱/프로젝트 설정에서 확인한다. 전환 여부를 검증할 수 없으면 미검증으로 기록한다. 사용자가 원본 참조를 선택하면 그 외부 의존성과 보관 시 필요한 조치를 기록한다.

## 납품 파일명

개별 납품 문서·이미지·영상·음원·프로젝트 압축파일: `YYYY-MM-DD HH'mm 기존 파일명.확장자`. 사용자 작업 시간대를 확인해 사용하고 호스트 시간대와 혼동하지 않는다. 같은 결과물을 다시 만들 때 날짜·시간 접두사만 교체한다. 최종·수정본·v2·(1) 같은 버전 표현을 덧붙이지 않는다. 같은 분에 이름이 충돌하면 덮어쓰거나 임의 접미사를 붙이지 말고 확인한다.

원본·프로젝트 내부 파일·소스 코드·실행 파일·설정·연결 자산·폴더·저장소·URL·기능상 고정 이름에는 적용하지 않는다. 프로젝트 ZIP은 외부 이름만 적용하고 내부 구조는 유지한다. 자동 설치·업데이트·플랫폼 등록용 배포 파일은 필요한 이름을 유지한다. 애매하면 기능과 경로 보존을 우선한다.

## 검증

실제로 저장한 파일을 다시 열거나 형식별 적합한 검사로 확인한다. 임시 파일을 납품본으로 표시하지 않는다. 기존 결과물과 원본을 보존하고 링크/미디어 연결이 바뀌었는지 확인한다. 외부 경로 기록은 개인별 절대경로를 최소화하고 프로젝트 내부 참조는 상대경로를 우선한다.


## 결과물 버전 보관

### 적용 범위와 최신안 묶음

새 결과물을 작성하거나 수정하여 저장·검증을 성공적으로 마친 때에만, 같은 결과물의 기존안을 해당 파일이 있는 폴더 아래 `이전안`으로 옮기고 상위 폴더에는 그 결과물의 최신안 묶음만 남긴다. `이전안`이 없으면 만든다. 이 통상 보관과 필요한 충돌 격리는 상시 승인된 절차이므로 매번 재승인을 묻지 않는다. 사용자가 별도 보관 방식을 지정하면 그 지시를 우선한다. 이 규칙의 설치·수정·프로젝트 열기만으로 과거 프로젝트 전체를 정리하지 않는다.

대상은 현재 작업이 대체한 결과물로 한정한다. 작업 요청·결과물 목적·내용·기존 기록으로 동일 결과물임을 확인하며 파일명 유사성, 날짜, 확장자만으로 판정하지 않는다. 다른 사업·기간·언어·수신자·용도의 문서나 사용자가 유지한 대안은 임의로 구버전으로 분류하지 않는다. 불명확하면 그 파일은 그대로 두고 확인한다.

최신 Word와 그에 대응하는 PDF처럼 함께 쓰는 형식은 한 묶음으로 유지한다. 이번 작업에서 필요한 형식을 확인하고 전체 묶음의 저장·검증이 끝나기 전에는 기존 묶음을 옮기지 않는다. PDF 생성 실패, 아직 확인하지 못한 영상·문서, 일부 형식만 완성된 상태라면 기존안을 그대로 유지하고 새 파일은 검증 미완료임을 기록한다. 단순히 가장 최근 파일 하나만 남기지 않는다. 서로 다른 폴더에 걸친 묶음은 각 기존 파일의 폴더 아래 `이전안`으로 보관하고 기록으로 묶음을 연결한다.

원본 자료·참고자료·소스 코드·설정·연결 자산·내부 작업 기록·기능상 고정 경로 파일은 이 규칙의 이동 대상이 아니다. 제작 파일을 결과물로 보관해야 한다면 참조·상대경로·앱 설정·연결 자산 의존성을 먼저 확인한다. 안전한 이동을 검증할 수 없거나 연결 수정·자산 이동 등 범위 확대가 필요하면 해당 제작 파일은 유지하고 필요한 조치를 확인한다. 관련 소스를 최신 결과물과 함께 무조건 옮기지 않는다.

### 안전한 저장과 이동

1. 기존안 목록과 최신안 묶음, 사용자 보관 예외를 확인한다. 새 결과물은 기존 파일을 덮어쓰지 않는 별도 이름/경로에 저장한다. 앱이 덮어쓰기만 지원하면 작업 전에 기존 바이트를 안전하게 복사·검증하여 보존하고 원본 경로는 새 결과물 검증 전까지 유지할 수 있는 방법을 택한다. 그것이 불가능하면 중단하고 방법을 확인한다. 새 결과물이 동명이어야 하는 제약은 납품 이름 충돌로 다루며 기존안을 먼저 이동해 자리를 비우지 않는다.
2. 새 묶음 전체에 필요한 형식별 검증을 마친다. 단순 파일 존재나 쓰기 성공만으로 내용·렌더링 검증이 완료됐다고 판단하지 않는다. 실패·미완료이면 기존안을 이동하지 않는다.
3. 이동 직전에 기존안의 경로·크기·해시와 참조 상태를 확인한다. 공유 폴더에서는 [공유 작업](shared-work.md)의 동시 변경·접근·동기화 확인도 적용한다. 비교 후 내용이 바뀌거나 열림/잠금/동기화 상태로 안전성이 불확실하면 관련 이동을 보류한다.
4. 보관 목적지의 실제 정규화 경로가 해당 프로젝트의 기존안 폴더 아래인지 확인한다. 정션·심볼릭 링크로 벗어나지 않게 한다. 원래 파일명과 내용을 유지하여 덮어쓰기 없는 이동을 수행한다. 삭제 명령, 강제 덮어쓰기, 자동 중복 제거로 보관을 대신하지 않는다.
5. `이전안`에 동명 파일이 있으면 크기·해시 등으로 내용을 확인한다. 같은 내용이어도 자동 삭제·합치기하지 않는다. 기존 보관본을 유지하고 새 보관 대상은 `이전안/보관시각-구분값/원래 파일명`처럼 중복되지 않는 하위 폴더에 원래 이름 그대로 이동한다. 형식 묶음이면 같은 구분 폴더에 모은다. 구분 폴더 생성도 충돌을 확인하며 기존 폴더를 덮어쓰지 않는다. 내용을 확인할 수 없는 충돌이면 원본을 유지하고 알린다.
6. 이동 전후 파일 수·크기·해시로 보존을 확인하고 최신안 묶음이 상위에 남았는지 재조회한다. 이동을 하지 않기로 한 파일은 이유를 기록한다. 묶음 이동이 일부만 성공하면 나머지 이동을 멈추고 원래 경로가 비어 있고 안전한 경우에만 되돌린다. 덮어쓰기를 요구하는 복구는 하지 않는다. 실제 위치와 미완료 상태를 기록하여 전체 완료로 보고하지 않는다.
7. 프로젝트 안내·인계 문서의 현재 결과물 경로와 링크를 최신안으로 갱신하고 기존안의 실제 보관 위치·검증 결과를 기록한다. 과거 기록은 지우지 않고 이전 경로와 새 보관 위치를 연결한다. 링크 대상 존재를 확인한다. 기록 경로가 없으면 기록 생성 승인 절차를 따르며, 갱신이 막히면 미완료로 보고한다.

이동 검증과 기록 갱신까지 끝나야 버전 보관 완료로 보고한다. 최신안만 남긴다는 목표를 위해 예외 자료를 강제로 이동하거나 검증을 생략하지 않는다.
