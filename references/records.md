# 작업 기록과 재개

## 승인과 기록 범위

기록 위치가 승인되어 있으면 중요 결정·수정·검증 단계마다 갱신한다. 없으면 아래 공통 기록 위치 기준에 따라 `AI Worklog/프로젝트 안내.md`와 `AI Worklog/대화명/`의 생성안을 한 번에 제안하고 승인받는다. 승인 대기 중에는 채팅에 인계 내용을 남길 수 있으나 몰래 다른 폴더에 저장하지 않는다. 명시적으로 기록 저장을 요청한 경우 그 범위는 재승인하지 않는다.

단순 질문마다 파일을 만들지 않는다. 이미 수행한 작업과 승인된 결정을 기록하며 추측·미검증·계획을 분리한다. 기록 파일은 내부 파일이므로 납품용 날짜 접두사를 강제하지 않는다. 공용 기록에 인증정보·불필요한 개인 대화·비공개 원본 전체를 복제하지 않는다. 공개 배포 패키지에는 내부 기록을 기본 포함하지 않는다.

## 공통 기록 위치

새 AI 대화·작업 기록의 기본 위치는 `AI Worklog/대화명/`이다. Codex, Claude Code, Gemini CLI 등 사용 도구가 달라도 같은 공통 기록 폴더를 사용한다. 도구·모델별 상위 폴더는 추가하지 않고, 사용 도구와 확인 가능한 대화 ID는 기록 안에 남긴다. 사용자 지정 이름과 기존 승인된 기록 위치가 우선한다.

기존 `AI Worklog` 및 같은 역할의 기록 위치를 표기·대소문자 차이까지 확인한다. 기존 `codex`, `claude`, `ai`, `작업기록` 등의 기록은 자동 복제·개명·이동·통합하지 않는다. `AI Worklog`로 전환하려면 대상과 경로를 제안하고 승인받은 뒤 원본 보존·연결 확인·이동 검증·링크 갱신 절차를 적용한다. 이 스킬의 업데이트는 기존 프로젝트의 일괄 이동 승인이 아니다.

진행 중인 대화는 승인된 기록 위치를 재사용한다. 새 대화로 재개하면 승인된 공통 기록 위치에 새 기록을 남기고 이전 기록을 상대경로로 연결한다. 도구 변경만으로 기록을 복제하지 않는다. 프로젝트 공통 안내가 이미 있으면 재사용하고 연결하여 기준 안내를 중복 생성하지 않는다. 새 폴더는 실제 기록이 필요하고 생성이 승인된 경우에만 만든다.

이 기준은 AI 대화·결정·검증·인계 기록에 적용한다. AI 생성 이미지·영상 등 결과물과 제작 소스는 파일 관리 기준의 실제 용도별 폴더에 유지하고, 도구의 시스템 설정·스킬 설치 경로는 바꾸지 않는다.

## 대화 폴더

사용 가능한 실제 대화 ID와 제목을 확인한다. 없으면 제목을 지어 사실처럼 표시하지 말고 작업명으로 폴더를 제안한다. 매핑 기록에는 사용 도구와 제목, 확인한 대화 ID 또는 승인된 로컬 작업 ID, 기록 범위를 둔다. 같은 도구와 대화 ID 조합의 기록이 있으면 재사용한다. 다른 도구의 동일 ID를 같은 대화로 간주하지 않는다. 제목 변경으로 폴더를 자동 복제·이동하지 않는다. 동명인 다른 대화는 짧은 ID를 붙인 이름 등 구분안을 승인받는다. [공유 경로와 파일명](files.md)의 수신 환경 제약을 적용하며 원래 제목은 기록에 보존한다.

## 최소 기록

프로젝트 안내: 목적, 승인된 분류, 현재 기준 제작 파일·결과물, 관련 대화 기록, 다음 재개 지점. 대화별 인계: 요청·결정·승인 범위, 현재 상태, 변경 파일, 검증과 한계, 미완료, 재개 방법, 의존성. 필요한 항목만 [인계 양식](../assets/handoff-template.md)을 참고해 작성한다. 불필요한 양식 빈칸은 남기지 않는다.

대화 원문은 접근 가능한 사용자·어시스턴트 표시용 내용만 범위를 명시하여 보존한다. 숨겨진 추론·시스템 지침·도구 인증 출력은 추출하지 않는다. 요약을 대화 원문으로 표시하지 않는다. 세션 로그를 통째로 복사하지 않는다. 원문이 없어도 인계 문서만으로 재개할 수 있게 한다.

승인된 폴더 분류는 폴더 이름뿐 아니라 역할·적용 범위와 함께 프로젝트 안내에 기록한다. 실제 재분류를 수행한 경우 기존 경로→현재 경로와 링크, 보존 검증·제외 자료·남은 의존성을 인계에 남긴다. 분류 기준은 [파일 관리](files.md#영상-프로젝트의-문서와-제작-자료-분류)를 참조하며 여기서 별도 폴더 구조를 강제하지 않는다.

프로젝트 내부 파일은 상대경로로 연결한다. 외부 의존성은 위치·확보/재연결 방법·권한 또는 라이선스 제약을 기록하되 비밀값은 제외한다. 앱 버전·폰트·플러그인·모델·렌더 설정·실행 명령 중 재현에 필요한 것만 남긴다. API 자격증명은 보관 위치 또는 설정 방법만 기록한다.

## 결과물 버전 보관 기록

새 결과물 검증 후 기존안을 정리할 때는 [파일 관리의 결과물 버전 보관](files.md#결과물-버전-보관)을 적용한다. 이 문서는 이동 기준을 중복 정의하지 않는다. 현재 결과물 묶음의 경로·상태, 기존안 원래 위치→실제 보관 위치, 이동 전후 검증, 예외·실패·미완료를 기록한다. 프로젝트 안내와 인계의 현재 링크는 최신안으로 갱신하고 링크 존재를 확인한다. 이전 결정·작업 이력은 보존한다. 내부 기록 자체는 결과물 구버전으로 이동하지 않는다.

## 프로젝트 전체 보관

보관 요청 범위 안에서 필수 소스·편집 프로젝트·결과물·연결 자산·기록을 점검한다. 외부 자료 반입은 파일 관리의 승인 절차를 따른다. 보관 매체로 복사했다면 파일 수·크기와 중요 파일 해시를 비교하고, 가능한 열기·실행·연결 검증을 수행한다. 원본 삭제나 사용 중인 AI 도구의 대화 삭제는 별도 요청 없이는 수행하지 않는다. 검증하지 못한 파일·외부 의존성은 명시한다.

## 재개

현재 지정된 루트에서 안내와 관련 인계를 읽고 실제 파일 상태를 확인한다. 과거 절대경로로 이동하거나 루트를 재생성하지 않는다. 기록과 현재 상태가 다르면 확인한다. 과거 승인 기록을 새로운 설치·전송·삭제 승인으로 확대하지 않는다. 새 대화의 작업은 이전 기록에 연결하여 보존하고 최신 안내를 갱신한다. 이전 이력을 지우지 않는다. 필요한 읽기만 수행하고 모든 자료를 무조건 재검사하지 않는다.
